# 보고자료 시각화와 편집용 다이어그램

## 구성 제안: 기본 작업

문서 정보를 충분히 모으면 비교 표와 그림의 구성을 먼저 판단한다. 사용자가 그림을 요청하지 않았거나 템플릿에 위치 주석이 없어도 적용한다. 변경 전후와 대안은 [비교 표 규칙](comparisons.md)을 먼저 따른다.

표만으로 충분하면 필요한 표의 위치를 짧게 안내하고 그림 없이 작성한다. 의미 있게 다른 구성이 있으면 실제 내용에 맞는 2~3개 구성안을 제시한다. 형식적으로 세 안을 채우거나 같은 그림을 여러 안으로 바꾸지 않는다.

| 구성안 | 표·그림 구성 | 적합한 경우 |
| --- | --- | --- |
| 1안: 간결형 | 비교 표 중심, 필요한 경우 핵심 그림 0~1개 | 짧은 보고·단순 변경 |
| 2안: 기본형 | 핵심 비교 표와 필요한 구조·흐름 그림 1~2개 | 일반 완료보고·설계 설명 |
| 3안: 상세형 | 전체 구조와 필요한 핵심 흐름·예외 그림 | 여러 구성 요소나 복잡한 분기 설명 |

위 수량은 예시 범위다. 제안할 때는 **각 안의 실제 그림 수·종류·넣을 섹션·전달할 정보·생략하는 정보**를 적는다. 예를 들어 `2안: As-Is/To-Be 표 + 처리 흐름도 1개(추진내용)`처럼 보여준다. 상세형도 근거 없이 그림 수를 늘리지 않는다. 장식용 이미지·빈 그림은 어느 안에도 넣지 않는다.

추천안이 있으면 필요한 이유를 짧게 설명하고 구성 선택을 묻는다. 선택이 필요한 경우 답변 전에는 그림을 생성하거나 최종 문서를 전달하지 않는다. 이는 문서 구성 질문이며 페이지 게시 승인이 아니다. 답변 없음이나 경과 시간으로 선택을 확정하지 않는다.

이미 `표만`, `간결형`, `그림 1개`, `기존 그림 유지` 등 구성·수량을 지정했거나 `필요한 구성으로 알아서 작성`처럼 판단을 맡겼다면 그 범위에서 진행하고 다시 묻지 않는다. 가능한 구성이 하나뿐이면 그 이유를 알리고 진행한다. 기존 준비 상태 기준은 사실 정보와 함께 이 구성 선택도 확인한 뒤 적용한다.

템플릿의 목차는 유지하며 그림을 위해 섹션을 추가하지 않는다. 위치 주석이 없으면 선택한 구성의 목적에 맞는 기존 섹션에 넣는다. 현재 환경에서 PNG 생성이 불가능하면 원본 제공·내보내기 방식으로 가능한 범위를 제안한다. 생성할 수 없는 산출물을 제공한다고 약속하지 않는다.

## 생성 판단

템플릿의 `<!-- 시각화 ... -->` 주석은 배치 후보와 작성 지침이다. 기본은 선택이다. 구성 제안과 사용자 선택 후에도 각 그림에 다음 기준을 적용한다.

- 분기·반복·예외, 여러 구성 요소 사이의 관계, 비교·추이가 글이나 표보다 쉽게 전달될 때 생성한다.
- 단순한 순서, 관계가 없는 항목 나열, 이미 본문·표로 충분한 정보는 생략한다. 분량을 채우기 위한 장식은 만들지 않는다.
- 생성 조건과 생략 조건을 함께 적용한다. 필수 지정이어도 자료가 부족하면 추측하지 않고 확인한다.
- 생략한 위치에는 빈 그림, 자리표시자, '다이어그램 없음' 문구를 남기지 않는다. 작성용 주석은 최종 HTML과 Markdown에서 제거한다.
- 그림 생성 지시가 외부 업로드나 원격 렌더링 서비스 사용 권한을 뜻하지 않는다. 회사 자료는 사용 가능한 로컬 도구로 처리한다.

## 템플릿 문법

```markdown
## 처리 흐름

{{처리 흐름 설명}}

<!-- 시각화
id: process-flow
종류: 흐름도
필수 여부: 선택
목적: 정상 처리와 실패 시 분기를 보여준다.
생성 조건: 분기·반복·예외가 있어 글이나 목록만으로 이해하기 어려울 때
생략 조건: 단순한 순서이거나 본문·표의 정보를 반복할 때
출력: PNG + draw.io 원본
자료 부족 시: 생성하지 않는다
-->
```

id는 문서 안에서 고유하게 지정한다. 사용자가 준 기존 주석의 목적·종류·출력 필드도 해석한다. 필수 여부가 없으면 선택으로 취급한다.

## 산출물

기본은 `diagrams/<id>.drawio`와 `diagrams/<id>.png`다. 원본은 노드·텍스트·연결선이 개별 편집 가능한 draw.io XML로 만든다. 하나의 래스터 이미지나 SVG 전체를 감싼 파일을 편집용 원본이라고 부르지 않는다.

- `.drawio`는 비압축 `mxfile/diagram/mxGraphModel/root` 구조로 작성할 수 있다. 기본 셀 id 0과 parent=0인 id 1을 두고 도형은 vertex=1, 선은 edge=1로 만든다. 도형의 x/y/width/height와 연결선 source/target을 지정하고 실제 존재하는 셀을 참조한다. XML 텍스트와 속성을 이스케이프한다.
- PNG는 **동일한 그래프와 배치**를 렌더링한다. 로컬 draw.io 내보내기 또는 사용 가능한 로컬 렌더링 도구를 사용한다. native 원본과 내용이 다른 그림을 별도로 생성하지 않는다.
- 한글 폰트, 글자 잘림, 연결선의 겹침, 라벨과 화살표, 읽는 순서를 확인한다. 가능하면 draw.io에서 파일을 열어 개별 도형이 편집되는지 확인한다. XML 파싱만 했다면 앱 호환성 검증을 했다고 주장하지 않는다.
- PNG 생성 도구가 없으면 `.drawio` 원본을 제공하고 PNG 미생성 상태와 draw.io 내보내기 방법을 알린다. 설치나 원격 서비스를 자동 사용하지 않는다. 실제 생성하지 않은 파일 링크를 넣지 않는다.
- Mermaid는 사용자가 지정한 경우 `.mmd` 원본으로 제공할 수 있다. `.drawio`와 별도 형식이며 Confluence 기본 지원을 보장하지 않는다.
- 수치 차트는 실제 데이터를 사용하고 편집용 데이터도 함께 제공한다. `.drawio`를 수치 차트의 필수 원본으로 강제하지 않는다.

## HTML 배치와 Confluence 편집

미리보기 `.preview.html`의 지정 위치에 `figure/img/figcaption`으로 PNG를 배치한다. 문서와 diagrams 폴더를 함께 전달하며 상대 경로와 대체 텍스트를 사용한다. Markdown에도 동일 위치에 그림과 캡션을 넣는다. 원본 다운로드 링크와 설치 설명은 본문 밖의 전달 안내에 둔다.

입력용 `.body.html`에는 확인된 Confluence 첨부 URL이 있을 때만 이미지를 넣는다. URL이 없으면 해당 위치에 `그림 삽입 위치: <그림 제목>` 문단과 캡션을 넣고 실제 생성한 PNG/원본을 별도로 전달한다. 로컬 상대 경로를 회사 입력 창에서 표시 가능한 URL로 취급하지 않는다. 그림 생성을 생략했다면 이 삽입 표시도 넣지 않는다.

HTML 복사만으로 로컬 이미지가 첨부되거나 편집 가능한 draw.io 매크로가 생긴다고 주장하지 않는다. 안내에는 그림 id, 배치 섹션, PNG와 원본 경로를 대응시킨다.

1. `.body.html` 소스 전체를 Confluence HTML 소스 입력 창에 붙여넣고 적용한다.
2. draw.io 앱이 있으면 해당 위치에 draw.io Diagram 요소를 추가하고 원본 `.drawio`를 가져온다. 이후 그 요소에서 도형·텍스트·선을 편집한다.
3. 앱이 없으면 PNG를 첨부하고 원본을 보관한다. 수정 시 원본을 편집하고 PNG를 다시 내보내 교체한다.

매크로는 본문에 자동 삽입하지 않는다. 템플릿의 패널·접기·목차 지시는 대상 환경에서 지원되는지 확인하고 본문 밖의 삽입 안내로 전달한다. 일반 HTML을 Confluence storage 형식으로 취급하지 않는다.
